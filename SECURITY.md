# Security

These skills run inside Claude Code with whatever access your session has. Their scripts run locally: they install Playwright from npm into `~/.cache/killer-design` or `~/.cache/killer-repo`, call GitHub's API through your `gh` login (killer-repo), write council records under `~/.claude/council-runs` (killer-council), and write each other skill's records under `~/.claude/killer-<name>`. killer-bugs, killer-tests, killer-docs, killer-perf, killer-upgrade, killer-release and killer-goal run your project's code: in copies of it in the temp folder, with their own home and temp folders, no credentials or host import paths in the environment and, unless the run allows it, a dead proxy for the network. That's isolation by environment variables, not a container. killer-upgrade turns the network on by default, because installs need a registry, and a package's install scripts are code from the internet running in that copy. killer-goal can add a Stop hook to `~/.claude/settings.json`, only when you say yes; it backs the file up first, does nothing unless a goal is running, and `goal.py hook remove` takes out only its own entry. The installers download from this repo's GitHub releases, or copy from a folder of its release files, and check every archive against the release's `SHA256SUMS.txt`. Both unpack the font pack into `~/.cache/killer-skills-fonts`: Fontsource's packages from npm, each checked against the integrity hash pinned in `tools/fonts.json` when CI builds the pack. On Windows, `install.ps1` also unpacks the runtime (Playwright, Chromium and Mermaid, built in this repo's CI from the versions in `tools/runtime.json`) into `~/.cache/killer-skills`, and killer-design and killer-repo run Chromium from there. When Node.js or Python is missing, it unpacks the official nodejs.org or python.org download into `~/.cache/killer-skills-node` or `~/.cache/killer-skills-python`; CI checks each against the SHA-256 pinned in `tools/runtime.json` before packing it.

## Supported versions

Only the latest release gets fixes.

## Reporting

Use [private vulnerability reporting](https://github.com/Real-Fruit-Snacks/killer-skills/security/advisories/new). Don't open a public issue. I'll answer within a week.

Worth reporting: an installer that writes outside the skills folder and its four pack folders in `~/.cache`, or installs an archive that fails its checksum, a skill that changes something public (a repo's settings, a release, a push) without asking first, a council brief that leaks the threshold to its members, a sandbox that hands the project's code your credentials or writes into your real project, killer-release tagging, pushing or publishing without your OK in the session, or killer-goal's hook keeping a session going that isn't running a goal.
